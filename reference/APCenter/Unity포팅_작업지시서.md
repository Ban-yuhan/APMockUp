## 1. 절대 규칙 (어기면 안 됨)

1. **씬은 에디터에 존재해야 한다.** 런타임 코드로 정적 오브젝트를 `new GameObject` / `CreatePrimitive`로 만들지 않는다. 모든 시설·바닥·벽·트럭·캐릭터는 **씬 오브젝트 또는 프리팹으로 만들어 Hierarchy에 보이게** 한다. (사용자가 직접 수정하고 캐릭터 에셋을 적용해야 함)
   - 예외: 알바처럼 개수가 가변인 것은 프리팹 `Instantiate`.
2. **모델 교체가 가능해야 한다.** 플레이어/알바/트럭 프리팹은 루트(로직·콜라이더)와 `Model` 자식을 분리한다. 손에 드는 아이템 위치는 빈 오브젝트 `HandAnchor`. 형태는 큐브/실린더/캡슐 프리미티브로 시작한다.
3. **수치는 Inspector에서 조절 가능해야 한다.** `CONFIG`는 ScriptableObject, 개별 값은 `[SerializeField]`.
4. **로직과 뷰를 분리한다.** 게임 상태(`G`)와 규칙은 순수 C# 클래스(MonoBehaviour 아님)에 두고, 뷰(MonoBehaviour)가 상태를 읽어 표시한다. 원본의 역방향 호출(분석 §3-1: `S.spend → UI.toast`, `Albas.hire → World.addAlba` 등)은 **이벤트(`Action`)로 바꾼다.**
5. **원본 동작을 임의로 바꾸지 않는다.** 개선·단순화·밸런스 변경 금지. 바꾸고 싶으면 보고하고 승인받는다.
6. 요청하지 않은 기능(세이브, 모바일 대응, 사운드 등)을 추가하지 않는다.

### 좌표계 (중요)
Three.js는 오른손, Unity는 왼손 좌표계라서 **그대로 옮기면 좌우가 반전된다.**
- 변환 규칙 제안: `unity.x = three.x`, `unity.y = three.y`, **`unity.z = -three.z`**, 카메라 오프셋은 `(8, 48, -36)`.
- 회전: `faceYaw(rot)`, `truckYaw(rot)` 계산은 z 반전에 맞춰 부호를 조정한다.
- 변환은 **한 곳(예: `CoordUtil`)** 에서만 한다. 이 변환이 맞는지 **원본 화면(브라우저에서 index.html 실행)과 Unity 씬을 눈으로 비교**해 확인하고 사용자에게 보고한다.

## 4. 검증

- **불변식**: `js/main.js`의 `checkInvariants` 규칙을 읽어 C# 테스트로 옮긴다. 4단계부터 매 단계 통과해야 한다. (규칙은 문서가 아니라 소스에서 읽을 것)
- **정산 단위 테스트**: `LoadLogic.payout`, `fillMult`, `rankMult`, `canPlace`(압축 적재 포함)를 **원본에서 입력→출력 예시 3개 이상을 직접 실행해 뽑아** 같은 값이 나오는지 검증한다. (브라우저 콘솔에서 `LoadLogic` 호출 또는 Node로 실행)
- 컴파일 에러·콘솔 에러 0을 단계 완료 조건에 포함한다.
